PROJECT: VHR Imagery Processing Pipeline (Maxar -> Analysis Ready Data)
INFRASTRUCTURE: Google Cloud Workflows orchestrating Google Batch Jobs.

WORKFLOW STRUCTURE:
- All-in-One Job (CPU): A consolidated single-container workflow that processes all steps (Download -> Ortho -> CCDC -> TOA -> Cloud Mask -> Pansharpen -> SRLite -> COG -> GEE Seg Trigger).
- Relies on `run_job_all.sh` acting as the master execution script inside the `vhr-cpu` Docker image (includes CPU-only PyTorch and OmniCloudMask).
- Resumable: Intermediate syncing (`gsutil rsync`) is implemented to checkpoint progress (e.g., uploading 200_ortho and products incrementally) to handle potential Spot VM preemptions gracefully.
- COG Generation: In-place compression replaces raw `.tif` files immediately to conserve local disk space during long-running pipelines.
- Output Structure: Organizes output in dynamically generated GCS folders using `strip_id` (YYYYMMDD_HHMMSS_WV0X_CatID). Includes `order_metadata.json` and auto-generated GEE visualization scripts (`_viz.js`). 
- Standardization: All outputs use standardized band naming (blue, green, red, nir).

CAPACITY, COST & PERFORMANCE:
- Disks: Requires `pd-ssd` (minimum 400GB) to prevent disk I/O bottlenecks. SSD expansion factor requires disk sizing at ~3x-9x the raw input size (high-water mark tracked in logs). Dynamic allocation is implemented based on input size.
- CPU/Memory: Standard configuration runs efficiently on instances with 4-8 vCPUs.
- Run Modes: 
  - Normal Mode (0.5m Pan / 2.0m MS): Takes 4-6 hours.
  - Quick Mode (5.0m Pan / 20.0m MS, skips segmentation): Takes under 15 minutes.
- Cost savings: The transition to single-container removed inter-job GCS overhead and GPU wait times. Resumability unlocks ~70% cost reduction by allowing Spot provisioning.
